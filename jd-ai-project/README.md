# 식품 제조 AI 워크벤치

식품 제조 공장의 **생산기술 · 품질관리 · 품질보증** 업무에서 반복되고 수작업이 많은 지점을 찾아 AI를 붙인 웹 서비스입니다.
직무를 고르면 그 직무의 업무 흐름과 AI 도구만 남습니다.

> 가상의 식품회사 데이터로 만든 시연용 개인 프로젝트입니다. 실제 회사의 데이터·시스템과 무관하며, 데이터와 법규 조문은 모두 가상입니다.

![첫 화면: 직무를 고르면 그 직무의 업무와 AI 도구가 보입니다](docs/screenshots/01-overview.jpg)

## 이 프로젝트가 풀려는 문제

채용공고의 직무 설명(생산기술·품질관리·품질보증)을 업무 단위로 풀어 쓰고([analysis/01-tasks.md](analysis/01-tasks.md)), 반복성·수작업 비중·AI 적합도로 개선 후보를 골랐습니다([analysis/02-problems.md](analysis/02-problems.md)).
그중 **데이터가 있고, 틀렸을 때 사람이 확인할 수 있는** 업무 8개를 도구로 만들었습니다.

## 핵심 설계: 코드가 계산하고 검증하고, AI는 해석한다

| | 맡은 일 |
|---|---|
| **코드** | 숫자 계산, 이상 탐지, 그리고 **AI가 한 말이 사실인지 검증** |
| **AI (Claude)** | 해석, 원인 추정, 문서 초안 |
| **사람** | 최종 판단 (합격·보류, 회수, 공문 발송) |

AI는 숫자를 틀리거나 없는 내용을 지어낼 수 있습니다. 그래서 틀리면 안 되는 부분은 코드가 맡습니다.

![관리도: 규격 안이어도 서서히 나빠지는 변화를 코드가 찾고, 그 의미는 AI가 설명합니다](docs/screenshots/02-control-chart.jpg)

- **계산은 코드가 합니다.** 관리도·공정능력(Cpk)·추세·수율은 AI에게 맡기지 않습니다. AI에는 계산된 결과만 넘기고 "다시 계산하지 말라"고 합니다.
- **AI의 인용은 원문과 대조합니다.** AI가 "조문에 이렇게 적혀 있다", "메모에 이렇게 적혀 있다"고 인용한 구절을 코드가 원문과 글자 단위로 대조해 `원문 일치` / `불일치`로 표시합니다.
- **없는 정보는 지어내지 않고 되묻습니다.** 현장 메모에 없는 시각·수량·담당자는 "현장에 되물을 질문"으로 돌려줍니다.
- **빈 응답은 걸러서 다시 받습니다.** 모델이 형식만 맞추고 `"placeholder"`로 비운 응답, 문제 항목이 빠진 응답은 거절하고 다시 요청합니다.
- **책임을 단정하는 표현은 경고합니다.** 협력업체 공문에 "배상", "귀사의 책임" 같은 표현이 들어가면 코드가 문맥과 함께 잡아냅니다.

## 도구 8종

| 직무 | 도구 | 코드가 하는 일 | AI가 하는 일 |
|---|---|---|---|
| 생산기술 | 생산지표 분석·보고서 | 수율·가동률 계산, 이상치 탐지 | 원인 가설, 보고서 초안 |
| 생산기술 | 설비 이상 진단 | 정상 기준선 대비 이탈, 고장 전조 추출, 위험도 | 예상 고장 유형, 정비 계획, 경보 기준 제안 |
| 품질관리 | 검사 데이터 이상 탐지 | 관리도, Cpk, 평균 이동, 추세("약 4일 뒤 규격 하한 도달") | 이상의 의미, 원인 추정, 조치 |
| 품질관리 | 부적합 보고서 초안 | 메모 인용을 원문과 대조 | 표준 양식 초안, 5Why, 되물을 질문 |
| 품질관리 | 법규 개정 영향도 | 조문 인용을 원문과 대조, 붙여넣은 조문을 조 단위로 분할 | 품목별 영향도, 조치 항목 |
| 품질보증 | 클레임 분류·회신 초안 | 입출력 스키마 검증 | 유형·심각도 분류, 조사 항목, 회신 초안 |
| 품질보증 | 위생점검 분석 | 반복 지적, 기한 초과 시정조치, 여러 공장 공통 문제 집계 | 원인 추정, 다음 점검 중점, 월간 보고서 |
| 품질보증 | 협력업체 통보서 초안 | 메모 인용·업체 과거 이력 대조, 책임 단정 표현 경고 | 공문 초안, 발송 전 확인 사항 |

![협력업체 공문: 귀책이 불명확해서 "우리 쪽에서 먼저 확인할 것"을 따로 제시하고, 인용은 모두 원문과 대조합니다](docs/screenshots/03-supplier-letter.jpg)

## 일부러 심어 둔 이상으로 검증했습니다

샘플 데이터에는 도구가 찾아야 할 정답을 심어 두었습니다([sample-data/README.md](sample-data/README.md)). 예를 들어 검사 데이터에는 이런 것들이 있습니다.

| 항목 | 심어 둔 상황 | 도구가 낸 결과 |
|---|---|---|
| 햄 중량 | 6/20부터 평균 하락, 규격 하한 미달 3건 | **위험 높음** (Cpk 0.58) |
| 소시지 염도 | 서서히 상승, 규격 안 | **주의** (평균 이동 + 추세) |
| 우유 지방률 | 안정 | **정상** (오탐 없음) |

설비 데이터에서는 "전조가 있던 고장"과 "전조 없이 갑자기 난 고장"을 구분해서 보여줍니다. 테스트 161개가 이 정답을 계속 확인합니다.

## 만들면서 확인하고 고친 것

- **응답 시간.** AI 응답에는 25~80초가 걸립니다. 코드 계산 결과(관리도 등)는 AI를 기다리지 않고 먼저 표시해 0.15초에 나오게 했고, 경과 시간과 취소 버튼을 넣었습니다. 취소하면 서버의 Claude 호출도 실제로 멈춥니다.
- **인용 대조 오탐.** 실제 Claude 응답을 돌려 보니 AI가 인용문 앞에 "제2조:"를 붙여서, 정상 인용이 "불일치"로 표시됐습니다. 조 표시와 공백을 정규화하도록 고치고 이 사례를 테스트로 고정했습니다.
- **빈 응답.** 검사 도구가 한 번 `"placeholder"`만 채워 돌려준 적이 있어서, 이런 응답을 거절하고 다시 받는 안전장치를 모든 도구에 넣었습니다.

## 기술

TypeScript · Hono · React · Vite · zod · vitest · Claude Agent SDK(로컬 Claude 로그인, API 키 불필요)

```
src/server/domain/        계산 로직 (통계, 관리도, 설비 진단, 위생점검 집계)
src/server/application/   LLM 포트, 도구 8종
src/server/core.ts        HTTP 앱 (Node와 브라우저에서 같은 코드로 동작)
src/web/                  React 화면
```

## 실행

Claude 로그인이 필요합니다. 자세한 방법은 [app/README.md](app/README.md)를 보세요.

```bash
cd app
npm install
npm run dev:server   # API 서버 (터미널 1)
npm run dev:web      # 화면 (터미널 2) → http://localhost:5173
```

로그인 없이 화면만 보려면 `npm run dev:demo`를 서버 대신 실행하세요(가짜 응답, 화면 상단에 "데모 모드" 표시).

### 웹에서 바로 보기 (설치 불필요)

**https://huijae1234.github.io/food-ai-workbench/** 에서 열립니다. 샘플 입력의 AI 결과는 미리 실행해 둔 실제 Claude 응답이고, 숫자 계산·관리도·검증은 브라우저에서 다시 실행됩니다. 직접 입력한 내용의 AI 분석은 아래처럼 로컬에서 실행해야 합니다(Claude 로그인을 쓰는 구조라서 공개 서버로는 돌리지 않습니다).

### 링크로 열 수 있는 단일 파일 버전

`npm run build:artifact`로 서버 없이 도는 HTML 파일 하나를 만들 수 있습니다. 같은 도구 코드가 브라우저에서 실행되고, 샘플 입력의 AI 응답은 **미리 실행해 둔 실제 Claude 응답**을 보여줍니다([app/README.md](app/README.md)).

## 한계

- 데이터는 전부 가상입니다. 실제 설비·검사·법규 데이터로 검증하지 않았습니다.
- 직무 설명이 짧아서, 업무 목록의 상당 부분은 일반적인 식품 제조 업무로 풀어 쓴 추정입니다.
- AI 결과는 초안입니다. 합격·보류 판정, 회수, 공문 발송은 사람이 합니다.

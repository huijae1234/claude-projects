# 02. 문제 파악 & AI 개선 후보 (생산기술 · 품질관리 · 품질보증)

평가 기준: **AI 적합도** = 반복성 × 텍스트/정형데이터 중심 × 오류 시 영향도 낮음(사람이 최종 확인 가능) × 로컬 Claude로 구현 가능
(★ 1~5, 5가 가장 적합)

## 직무별 문제 → AI 후보

### 생산기술
| # | 문제 | AI 개선안 | 적합도 | 비고 |
|---|---|---|---|---|
| P1 | 일/주/월 생산지표를 엑셀로 취합하고 보고서를 수작업 서술 | 지표 파일 업로드 → 요약·이상치 하이라이트·보고서 초안 | ★★★★★ | 엑셀/CSV만 있으면 구현 가능 |
| P2 | 수율·불량 이상 발생 시 원인을 경험에 의존해 추적 | 데이터+현장 메모 → 원인 가설 후보, 5Why 초안, 확인 체크리스트 | ★★★★ | 근거 제시형으로 설계 |
| P3 | 설비 정지·미니스톱 기록이 자유서술이라 분류·집계 불가 | 정지 사유 텍스트 자동 분류 → 파레토 | ★★★★ | 분류 체계 필요 |
| P4 | 품목 전환·생산 순서 최적화 | 제약조건 기반 순서 제안 | ★★ | 최적화 솔버 영역, LLM 단독은 부적합 |

### 품질관리
| # | 문제 | AI 개선안 | 적합도 | 비고 |
|---|---|---|---|---|
| Q1 | 식품 관련 법규 개정을 사람이 찾아 읽고 영향도 판단 | 개정 고시/조문 입력 → 요약, 자사 품목·공정 영향도, 조치 항목 | ★★★★★ | JD에 "개정법규 모니터링" 명시 |
| Q2 | 검사 성적·SPC 데이터에서 이상 징후를 늦게 발견 | 검사 데이터 업로드 → 관리도·규칙 위반 탐지 + 해설 | ★★★★ | 탐지는 통계 코드, 해설은 Claude (JD "이상탐지") |
| Q3 | 부적합 보고서(NCR) 작성이 번거롭고 품질이 들쭉날쭉 | 현장 메모 → 표준 양식 NCR 초안, 부족 정보 질문 | ★★★★★ | 입력이 메모, 출력이 문서 |
| Q4 | 입고 성적서(COA)를 규격과 수작업 대조 | COA 텍스트/PDF vs 규격 → 적합 여부·이탈 항목 | ★★★★ | PDF 파싱 필요 |

### 품질보증
| # | 문제 | AI 개선안 | 적합도 | 비고 |
|---|---|---|---|---|
| A1 | 소비자 클레임 접수문 분류·원인 조사·회신문 작성에 시간 소요 | 클레임 텍스트 → 유형 분류, 심각도, 조사 항목, 회신 초안 | ★★★★★ | 텍스트 중심, 반복 많음 |
| A2 | 위생점검 지적사항 관리(시정 이행 추적, 재발 패턴) | 점검 메모 → 구조화, 반복 지적 패턴 분석, 보고서 | ★★★★ | |
| A3 | 제품 표시사항(알레르기·영양성분)의 법규 적합성 검토 | 표시 문구/배합표 입력 → 체크리스트 대조 결과 | ★★★★ | 법규 DB를 직접 넣어 환각 방지 |
| A4 | 협력업체 평가·감사 서류 검토 | 서류 요약, 감사 체크리스트 생성 | ★★★ | 서류 확보 어려움 |

## 직무 공통으로 재사용 가능한 엔진
- **문서 구조화**: 자유서술 → 표준 양식 (Q3, A1, A2, P3)
- **기준 대조**: 입력 vs 법규·규격 (Q1, Q4, A3)
- **데이터 해설**: 지표/통계 → 이상치·원인 가설·보고서 (P1, P2, Q2)

→ 세 엔진을 만들면 직무별 기능은 "프롬프트 + 입력 양식" 차이만으로 구성 가능.

## 서비스 구조 제안: "직무 선택형 AI 워크벤치"

```
[직무 선택 화면]  전체 | 생산기술 | 품질관리 | 품질보증
       │
       ├─ 전체: 세 직무의 업무·문제·AI 도구를 한눈에 (탐색 모드)
       └─ 직무 선택 시: 그 직무의 업무 흐름 + 해당 AI 도구만 노출 (집중 모드)
                         각 도구 = 입력 양식 → Claude 처리 → 결과(근거 표시) → 내보내기
```

- 인증: 로컬에 로그인된 Claude(Claude Code/Agent SDK) 사용, API 키 불필요
- 구조: 로컬 웹 서버(백엔드가 Claude 호출) + 브라우저 UI
- 직무 추가/수정이 쉽도록 도구를 설정 파일(JSON)로 정의

## 한계/주의
- 실제 오뚜기 사내 데이터는 없으므로 **가상 샘플 데이터**로 시연해야 함 (기밀 데이터 사용 금지)
- 법규는 환각 위험이 커서 조문 원문을 입력받아 그 범위 안에서만 답하게 설계
- AI 결과는 "초안·제안"이며 최종 판단은 사람이라는 UI 문구 필요

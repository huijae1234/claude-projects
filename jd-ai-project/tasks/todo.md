# 식품 제조 AI 워크벤치 — 구현 계획

## 컨셉
식품 제조업(가상의 식품회사)의 **생산기술 · 품질관리 · 품질보증** 업무를 AI로 돕는 로컬 웹 서비스.
상단에서 직무를 고르면 그 직무의 도구만 보이고(집중 모드), "전체"에서는 세 직무를 모두 탐색한다.

## 기술 방향
- 인증: 로컬에 로그인된 Claude Code 인증을 Claude Agent SDK로 호출 (API 키 불필요, 폴백 `claude -p`)
- 서버: Node + TypeScript + Hono (로컬), 출력은 zod 스키마로 강제, 스키마 불일치 시 1회 재시도
- 웹: Vite + React, `/api` 프록시
- 저장: `data/<컬렉션>/<id>.json` 파일 저장 (이식 용이)
- 구조: `domain / application / infra` 레이어, LLM은 `LlmClient` 포트 + 테스트용 `FakeLlmClient`
- Claude 호출은 `settingSources: []`, `tools: []`로 격리 (순수 텍스트 입출력)

## MVP 도구 (직무당 1개)
| 직무 | 도구 | 입력 → 출력 |
|---|---|---|
| 생산기술 | 생산지표 분석·보고서 | CSV(생산량·수율·불량·가동률) → 이상치, 원인 가설, 보고서 초안 |
| 품질관리 | 법규 개정 영향도 분석 | 개정 조문 원문 + 자사 품목 카드 → 요약, 영향 품목, 조치 항목 |
| 품질보증 | 클레임 분류·회신 초안 | 클레임 접수문 → 유형, 심각도, 조사 항목, 회신 초안 |

## 메모 (Phase 0)
- Node.js LTS(v24)를 winget으로 설치함. 새 터미널에서는 PATH가 잡힘.
- Claude 호출은 `Not logged in`으로 실패: 데스크톱 앱 세션 밖의 Node 프로세스는 앱 내부 인증을 못 쓴다.
  → SDK 번들 `claude.exe`로 한 번 로그인(`auth login`)하면 `~/.claude`에 인증이 저장되어 해결.
- `ClaudeAgentLlmClient`가 `is_error` 결과를 성공으로 처리하던 버그를 수정함.

## 실제 Claude 검증 결과 (로그인 후)
- 생산지표 24.0초 / 법규 R-001 13.4초, R-002 25.2초 / 클레임 CL-001 15.7초, CL-003 25.2초, CL-008 11.6초. 전부 200.
- 법규: 인용문 10건 모두 원문 일치(citation_verified). 데이터 공백(라인 정보 없음)을 스스로 지적함.
- 클레임: 긴급(CL-001 금속, CL-003 알레르기)과 단순 의견(CL-008)을 올바르게 구분, 기관 보고 검토 플래그 정확.

## 개선 후보
- 법규: 영향 없음(none) 품목에도 같은 인용문을 반복 출력 → none은 인용 생략하도록 프롬프트·스키마 조정
- 품목 카드 `lines`가 비어 있는 품목(식용유, 만두)을 채우면 알레르기 혼입 판단(제3조)이 가능해짐
- 응답 10~25초 → 진행 상태 표시 개선 또는 스트리밍
- 도구 추가: 부적합 보고서(NCR) 초안, 위생점검 지적사항 분석

# 문제 기록 — 불편 없이 시작한 개인 프로젝트

## 1. 문제 문장

**해당 없음.** "딱히 불편은 없고 그냥 만들고 싶다"를 직접 선택했다. 풀어야 할 불편을 지어내서 붙이지 않았다.

## 2. 5 Whys ("왜?" 기록)

하지 않았다. 불편이 없는 상태에서 "왜?"를 다섯 번 물으면 답을 만들어 내게 되기 때문이다.
(불편에서 시작한 기록은 `day4/문제기록.md`(마감), `day5/문제기록.md`(쉬는 시간) 참고.)

## 3. 진짜 원인

해당 없음.

## 4. 왜 만들었나 / 방법 비교

- **이유:** API 두 개를 조합해 하나의 화면을 만드는 연습.
  - **Dog CEO** — 품종별 개 사진 (키 없음)
  - **위키백과 한국어** — 품종 설명 한국어 요약 (키 없음)
- **모양:** 도감 탭(품종 고르면 사진 + 한국어 설명) + 퀴즈 탭(사진 보고 품종 맞히기). 품종 약 80개.
- **해결 방법 세 가지 표:** 풀 불편이 없어서 만들지 않았다.

## 5. 처음 문제가 줄었나

**해당 없음.** 불편에서 시작한 프로젝트가 아니라서 "문제가 줄었나"로 평가할 수 없다. 대신 "의도대로 동작하나"와 한계를 적는다.

**한 줄:** 품종 81개를 사진 + 한국어 설명으로 보여 주고 퀴즈도 낼 수 있다. 다만 이름표를 손으로 만들어서 품종을 늘리려면 하나씩 다시 검증해야 한다.

### 의도대로 동작하나 (확인한 것)
- **이름표 81개 전부 규칙 통과**: 정상 73개, 요약이 짧은 8개(레온베르거·미니어처 핀셔·바센지·바셋 하운드·시츄·아이리시 세터·아이리시 테리어·페키니즈), 틀린 문서 0개.
- **틀린 문서를 막는다**: "치와와" 동음이의 문서, "샤페이"(사람 문서로 연결됨)가 오면 설명을 보여 주지 않고 "확인할 수 없어요"로 바뀐다. 샤페이는 이름표에서 제외했다.
- **규칙 표 통과**: 검색(공백 무시·영어 키), 퀴즈 500문제 반복에서 보기 4개가 이름·위키 문서 모두 안 겹침, 직전 정답 반복 0번, 같은 seed면 같은 문제 순서, 점수 계산.
- **두 API 모두 실시간 200**: `dog.ceo/api/breed/shiba/images/random/3`, `ko.wikipedia.org/api/rest_v1/page/summary/...`
- **실패 시험**: 위키 차단 → 고정 파일로 대체, 429 → 한 번 재시도 후 성공, Dog CEO 차단 → 고정 파일 사진 주소로 대체, 둘 다 차단해도 퀴즈 동작. 콘솔 에러 없음.
- **위키 캐시**: 같은 품종을 다시 고르면 위키를 새로 부르지 않는다(429 예방).
- **폰 폭(375px)**: 가로 넘침 없음.
- **캡처**(고정 파일 `?fixture=1&seed=1`): `캡처/1_도감_푸들_고정파일.jpg`, `2_퀴즈_문제_고정파일.jpg`, `3_퀴즈_정답_고정파일.jpg`, `4_폰크기_도감_고정파일.jpg`

### 만들다가 만난 함정 (실제로 걸린 것)
1. 동음이의 문서: "치와와", "사모예드", "복서"를 그대로 부르면 안내 문서가 온다 → "치와와 (개)", "복서 (개)"로 제목을 고정.
2. 엉뚱한 문서로 연결: "샤페이" → 사람 문서. `type`이 `standard`라 겉으로는 정상 → 요약에 개 품종 낱말이 있는지 보는 검사를 추가.
3. 그 검사가 처음엔 너무 깐깐했다: 진짜 개 문서 12개(보르조이·시베리안 허스키·웰시 코기 등)가 걸러졌다. 한국어 위키는 "개이다", "중형견으로", "애완견의", "송사견", 犬처럼 다양하게 쓴다 → 표현을 넓혀 81개 모두 통과.
4. 위키 `description` 필드는 69개 중 21개에만 있어서 판단 기준으로 쓸 수 없었다.
5. 위키를 연달아 부르면 429 → 간격을 두고 받고, 앱에서는 품종을 고르는 순간에만 한 번 부른다.

### 한계 (솔직하게)
- 이름표는 사람이 만들었다. 품종을 늘리려면 `tools/build_fixtures.py`에 후보를 추가해 다시 검증해야 한다.
- 규칙의 "개 문서인가" 검사는 낱말을 보는 어림짐작이다. 사람 문서가 우연히 "개의" 같은 표현을 담으면 통과할 수 있다. 이름표를 직접 검증한 것이 1차 방어이고, 이 검사는 안전망이다.
- 사진은 원격이라 인터넷이 필요하다. 고정 파일은 사진 주소만 저장한다.
- 위키 요약 길이가 품종마다 들쭉날쭉하다(짧은 8개는 안내만 한다). 일부 요약에는 위키 원문의 표현이 그대로 들어 있다.
- 퀴즈 사진 한 장이 그 품종을 대표하지 않을 수 있다(Dog CEO 사진은 무작위이고, 믹스견·다른 개가 섞여 보일 수 있다).

## 6. NVIDIA AI 연결 (나중에 추가)

**무엇을 했나:** 앱 이름("나한테 물어보시개!")에 맞게 **AI에게 물어보기**와 **쉬운 말로 풀어쓰기**를 붙였다. AI는 위키 설명(서버가 가진 검증된 요약)만 근거로 대답한다. 세 번째 API는 NVIDIA(build.nvidia.com)이고 키가 필요하다.

**구조:** 브라우저는 NVIDIA를 직접 부르지 않는다. `server.py`가 `.env`의 키로 대신 부른다. 키는 화면 코드·문서·로그 어디에도 없고, 서버는 `.env`, `server.py`, `tools/` 같은 파일을 내보내지 않는다. (`python server.py`로 열어야 AI가 된다. `python -m http.server`로 열면 AI 카드는 "쓸 수 없어요"가 나온다.)

### 모델은 이렇게 골랐다 (시험 결과)
- 키로 본 모델 목록은 80개인데, **실제로 대답한 모델은 9개뿐**이었다. (404 45개, 연결 실패 6개, 서버 오류 3개)
- 위키 요약(푸들)을 근거로 4문항 시험:
  - `gpt-oss-20b`: 가장 정직했다(근거 있음 → 답, 없음 → "나와 있지 않아요", 주제 밖 → 거절). 느리다(5~14초). → **질문 답하기에 사용**
  - `llama-3.2-11b-vision-instruct`: 빠르다(0.7~5초). 근거 밖 말을 섞은 적이 있었다. → **쉬운 말 풀어쓰기에 사용**(원문이 바로 위에 있어 검증이 쉽다)
  - `laguna-xs-2.1`: 아파트 질문에 위키에 없는 "네"를 지어냈고 쉬운 말은 30초, `</think>` 찌꺼기가 섞였다. → 쓰지 않음

### 확인한 것
- **보안**: `/.env`, `/server.py`, `/tools/…`, `/../.env` 등 12가지 경로가 모두 404. 정적 파일·API 응답·페이지·브라우저 저장소 어디에도 키 없음. 브라우저가 NVIDIA를 직접 부른 횟수 0. 같은 와이파이 주소로도 `.env`가 막힘.
- **서버 규칙**: 빈 질문·1자·81자·모르는 품종·깨진 JSON → 400, 같은 와이파이 사용자를 위해 IP당 분당 6회·하루 200회 상한(7번째 → 429), 같은 질문은 캐시(NVIDIA를 다시 부르지 않음), `<think>` 찌꺼기 제거.
- **답변**: 위키에 있는 건 답하고(푸들 성격·원산지, 시바견 크기), 없는 건 "위키 설명에는 나와 있지 않아요"(+ 화면 배지), 날씨 같은 주제 밖 질문은 거절.
- **고정 파일 모드**(`?fixture=1`): 실제 NVIDIA 응답 13개(푸들·시바견 추천 질문과 쉬운 말)를 가공 없이 `fixtures/nvidia-samples.json`에 저장해 키 없이 같은 화면을 재현한다. 캡처: `캡처/5_AI_물어보기_고정파일.jpg`

### 한계 (솔직하게)
- **AI가 위키 문장을 살짝 바꿔 쓴다.** 실제로 "털 빠짐이 적다"는 위키 문장을 "털이 빠지지 않지만"으로 과장한 답이 한 번 나왔다. "위키 설명만 근거"라고 시켜도 완벽하지 않다. 화면에 "AI 답변 · 틀릴 수 있어요"를 적었다.
- **위키 요약이 짧으면 AI가 쓸 말이 없다.** 골든 리트리버(요약 70자)에 성격을 물으면 "나와 있지 않아요"가 나온다. 정직하지만 도움은 덜 된다.
- **느리다.** 질문 답은 5~14초. 로딩 문구를 넣었다.
- **사용 가능한 모델이 적다**(80개 중 9개). 모델을 고를 폭이 좁았다.
- **고정 파일 AI 샘플은 푸들·시바견 두 품종**의 추천 질문뿐이다. 다른 품종은 실시간에서만 AI가 된다.
- **같은 와이파이 링크를 연 사람도 AI를 부를 수 있다.** 상한으로 막았지만 완전한 인증은 아니다.
- **키가 채팅창에 노출됐다.** 과제가 끝나면 build.nvidia.com에서 키를 새로 발급받고 이 키는 폐기하는 것을 권장한다. (새 키는 `.env`의 한 줄만 바꾸면 된다.)

## 7. 도감 챗봇 (새 키로 추가)

**무엇을 했나:** 품종을 고르지 않고 **말로 물어보면** 도감 81품종에서 알맞은 품종을 찾아 위키 설명을 근거로 대답하는 **챗봇 탭**을 추가했다. 시작 선택지 5개와 직접 입력을 모두 받고, 답 아래에 "근거로 쓴 품종" 칩(누르면 도감으로 이동)과 아직 안 물은 다음 선택지를 보여 준다.

**구조:** 질문 → (NVIDIA 임베딩 `llama-nemotron-embed-vl-1b-v2`) 가까운 품종 3개 → 그 위키 설명만 근거로 `gpt-oss-20b`가 대답. 브라우저는 우리 서버의 `/api/chat`만 부르고, 키는 `.env`→`server.py`만 안다. 근거 품종 목록은 AI가 말한 이름이 아니라 **서버가 찾은 3개**를 그대로 보여 준다.

### 모델은 이렇게 골랐다
- 새 키도 모델 목록은 80개, 실제 대답한 건 8개. 챗봇 후보를 같은 질문 5개로 비교:
  - `gpt-oss-20b`: 근거에 충실, 3~8초 → **채택**
  - `diffusiongemma-26b`: 1.5~3.4초로 가장 빠르나 "푸종"처럼 없는 단어를 쓴 적이 있음
  - `nemotron-3-ultra-550b`: 충실하지만 4~20초
- 사진으로 품종 맞히기(`llama-3.2-11b-vision`)는 4장 중 1장만 맞혀서 쓰지 않았다. 번역 모델은 한국어 대신 아랍어를 냈고, 안전장치 모델은 20초 넘게 응답이 없었다.

### 주제 밖 질문 거르기 (점수 문턱 0.22, 사람이 정한 값)
- 강아지 질문 20개의 1위 유사도: 0.235~0.529 / 상관없는 질문 15개: 0.041~0.322 (고양이 질문만 0.322)
- 문턱 0.22 미만이면 **AI를 부르지 않고** 안내문만 준다. 시험 결과: "서울 날씨", "점심 뭐 먹을까", "파이썬 정렬", "비트코인", "축구 규칙" 5개 모두 NVIDIA 호출 1번(임베딩만).
- 간격이 좁다(0.192와 0.235 사이). 걸러지지 않은 질문은 AI의 시스템 프롬프트가 한 번 더 거절한다.

### 확인한 것
- **보안**: 프로젝트 안에서 키 문자열은 `day6/.env` 한 곳뿐이다(이전 키는 지움). 응답·정적 파일·페이지·브라우저 저장소에 키 없음, 브라우저가 NVIDIA를 직접 부른 횟수 0, `/.env` 404(와이파이 주소로도).
- **서버**: 빈/1자/81자 질문 400, 같은 질문은 캐시(NVIDIA 호출 안 늘어남), 7번째 호출 429.
- **화면**: 고정 파일 모드(선택지 5개 실제 응답 저장)로 선택지 → 답 → 근거 칩 → 도감 이동 → 대화 유지/지우기, 선택지 밖 질문 안내, 폰 폭(375px) 가로 넘침 없음. 캡처: `캡처/6_챗봇_고정파일.jpg`
- **실시간**: "털 안 빠지는 작은 개" → 푸들(근거: 푸들·요크셔 테리어·노퍽 테리어), "짖음이 적은 개" → 위키에 없다고 정직하게 답함.

### 한계 (솔직하게)
- **AI가 근거를 넘는 말을 한다.** "푸들은 작은 사이즈(토이 푸들)로도 키울 수 있어요"는 위키 요약에 없는 AI 자체 지식이었다. "푸들 vs 시바견"에서는 시바견 정보가 없다면서도 "푸들이 더 까다롭다"고 결론을 냈다("비교·결론 내리지 마"라고 시켰는데도). 화면에 "틀릴 수 있어요"를 적었다.
- **검색이 가끔 빗나간다.** "일본에서 온 개는?"의 근거 3개에 시바견이 빠졌다(아키타견·뉴펀들랜드·라사 압소). 상위 3개만 보기 때문이다. "초보자한테 좋은 순한 개"는 위키에 "온순하다"고 적힌 품종만 찾는다.
- **대화를 이어 받지 못한다.** 질문마다 따로 처리한다("그럼 크기는?" 같은 후속 질문 불가).
- **느리다.** 답까지 5~13초(임베딩 1초 + 답 4~12초). 로딩 문구를 넣었다.
- **재시도가 숨어 있을 수 있다.** 서버는 NVIDIA 오류 시 한 번 재시도한다. 한 번은 임베딩이 재시도돼 호출 수가 2로 센 적이 있다. 이제 재시도 이유가 서버 로그에 남는다.
- **고양이 질문(0.322)은 문턱을 통과**하므로 AI 프롬프트의 거절에 의존한다(실제 호출로는 시험하지 못함).
- **고정 파일 챗봇 샘플은 선택지 5개뿐**이다. 직접 입력은 실시간에서만 된다.
- **키가 채팅에 두 번 노출됐다.** 과제가 끝나면 두 키 모두 폐기하고 새로 발급받기를 권장한다.
